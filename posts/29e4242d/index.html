按使用范围组织数据

可以先分清三种情况：

数据 存放方式 示例
每个对象各有一份 结构体成员 pin、brightness、is_on
整个模块共享一份 源文件中的 static 变量 s_init_count、s_debug_flag
模块内部使用的固定值 static const 对象 MAX_BRIGHTNESS、MAX_PIN

先确定数据属于单个实例还是整个模块，再决定它是否允许修改。

区分 static 的使用位置

本系列涉及的三种常见用法如下：

使用位置 主要作用 使用时的考虑
文件作用域的函数 使函数具有内部链接 适合内部辅助函数
文件作用域的变量 使变量具有内部链接 适合模块共享状态
函数内的局部变量 在函数调用结束后保留值 需要考虑多次调用之间的状态依赖

前两种用法主要帮助组织模块。第三种会让后一次调用依赖前一次留下的数据，测试和调试时需要考虑这种影响。

实例数据分开保存，可以避免多个外设互相覆盖；模块数据通过接口访问，可以减少外部直接修改；固定参数明确为常量，可以保留参数约束。数据的修改范围清楚后，出现异常时也更容易定位。
