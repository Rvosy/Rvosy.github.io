C 语言 vs C++ 的接口机制

概念 C++ C 语言
纯虚函数 virtual void on() = 0 ops 槽位必须非 NULL
虚函数 virtual void on() ops 槽位可被覆盖
默认实现 基类提供实现 dispatch 里走默认函数
接口合同 抽象类声明 ops_is_valid() 检查

C 语言没有编译器帮你检查纯虚函数是否实现，所以你要自己写检查。

Linux 风格接口为什么常有 NULL

很多大型 C 框架把 ops 设计成”部分可选”。比如不是每个设备都支持 ioctl，所以调用前必须检查：

关键是：文档和代码都要说明哪些函数可选。

驱动接口不是堆函数指针

在设计 ops 时，必须想清楚：

设计问题 应该明确
哪些操作必须支持 初始化时检查
哪些操作可以不支持 dispatch 返回错误或默认实现
不支持时返回什么 统一错误码
默认行为是什么 写成明确函数
谁负责释放资源 deinit 合同

否则 ops 会从”解耦工具”变成”空指针雷区”。

ops 是接口合同，不是函数指针杂货铺。必选函数初始化时检查，可选函数调用前判断，能默认实现就集中默认实现。
