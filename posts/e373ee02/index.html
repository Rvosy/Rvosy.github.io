封装解决了”一个对象怎么组织”的问题。但项目继续发展，你会遇到新的问题：多个对象有一半字段和函数都一样。比如 GPIO LED、PWM LED、呼吸灯、RGB LED，它们都有开关状态、亮度、初始化状态，但具体点亮方式不同。

继承解决了一部分，行为差异还没解决

继承后，公共字段复用了。但不同 LED 的点亮方式仍然不一样：GPIO LED 写电平，PWM LED 设占空比，RGB LED 同时控制三个通道，呼吸灯启动定时器渐变。如果 led_base_on() 写死为 gpio_write()，PWM LED 就不适用了。

所以继承只解决公共数据和公共基础逻辑，不解决行为差异。行为差异要靠后面的函数指针和 ops 表。

C++ C
class Base LedBase_t
class Derived : public Base 结构体内嵌 LedBase_t base
父类字段 base.xxx
父类方法 led_base_xxx(&obj->base)
派生类字段 具体结构体自己的成员

嵌入式里很常见

嵌入式里经常有一类设备的多个具体实现——LED（GPIO/PWM/RGB）、存储（Flash/EEPROM/SD卡）、通信（UART/SPI/I2C）、传感器（温度/湿度/IMU）。它们常常有公共状态、公共配置、公共错误码。用 base 抽出来后，上层更容易统一管理。
