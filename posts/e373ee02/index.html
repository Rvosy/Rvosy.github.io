前面的封装让每个 LED 拥有独立数据。接下来考虑多种 LED 实现：GPIO LED、PWM LED、呼吸灯和 RGB LED 都需要记录状态，但各自还需要不同的配置。

本节通过结构体嵌套提取公共部分。这种写法可以实现类似继承的数据复用，C 代码仍然需要显式访问内嵌成员、调用公共函数。

基础成员的布局与取址

本系列将 base 放在具体结构体的第一个成员：

因此对象起始位置就是基础成员。取得基础指针时，直接使用 LedBase_t *base = &pwm_led.base; 即可。

需要区分两个概念：把 base 放在首位是一种布局约定，而 &pwm_led.base 是对成员取地址。即使成员不在首位，也可以这样取址。后面的 container_of 会根据成员偏移计算完整对象的地址。

复用数据后仍需处理行为差异

不同 LED 的点亮方式并不相同：GPIO LED 设置电平，PWM LED 设置占空比，RGB LED 可能控制三个通道，呼吸灯还需要定时改变亮度。

如果基础函数固定调用 gpio_write()，它就不能直接完成其他硬件的点亮操作。本节的结构体嵌套解决了公共数据和已有公共逻辑的复用；各类型的行为差异会在后续章节通过函数指针和 ops 处理。

结构体嵌套不会自动获得 C++ 的访问控制和类型转换规则。本系列借用“基类”“派生类型”等术语描述公共部分与具体实现，实际操作仍以 C 的成员访问和函数调用为准。

类似的组织方式也可用于存储设备（Flash、EEPROM、SD 卡）、通信接口（UART、SPI、I2C）或传感器（温度、湿度、IMU）。同类设备确实需要共用状态、配置或错误处理时，可以考虑提取公共部分。
